01 — Concept

What “external” actually means

A native BigQuery table stores its data inside BigQuery’s managed storage. An external table stores only the definition — format, schema hints and the list of Cloud Storage URIs. The bytes never leave your bucket; BigQuery reads them at query time.

IN PLACE

Data stays as Parquet in gs://. No ingestion job, no duplication, no BigQuery storage cost.

SCHEMA-ON-READ

Parquet carries its own schema, so columns and types are auto-detected. Override only if you must.

READ-ONLY

Query it like any table, but no DML. Files change → the table reflects them on the next read.

TRADE-OFF

Slower and less consistent than native tables. Ideal for a raw/exploration zone; promote hot data later.

03 — Build it

Step by step, with the entire code

Follow the spine top to bottom. Steps 1–2 are context (done in your PySpark project). Step 3 is the fastest path. Steps 4–7 upgrade it into a governed, cached BigLake table. Every block has a copy button.

1
Land Parquet in the raw zonealready implemented in your project
PySpark▶

Your Spark job writes partitioned Parquet to the bucket. Partitioning by a date column enables pruning later.

write_raw_zone.py
# PySpark — write on-prem data to the GCS raw zone as partitioned Parquet
(df.write
   .mode("overwrite")
   .partitionBy("dt")                 # yields dt=2026-01-01/ folders (Hive layout)
   .parquet("gs://my-raw-zone-bucket/sales/"))
2
Confirm the layout in Cloud Storagesanity-check the URIs BigQuery will point at
gcloud▶

Verify files are Parquet and partition folders exist. Note the bucket location — it must match the BigQuery dataset location.

shell
# List what landed
gcloud storage ls "gs://my-raw-zone-bucket/sales/"
# dt=2026-01-01/  dt=2026-01-02/  ...

# Check the bucket region (dataset must be co-located)
gcloud storage buckets describe gs://my-raw-zone-bucket \
  --format="value(location)"
3
Create a plain external tablefastest path — no connection needed
core▶

Point BigQuery at the Parquet. Because Parquet is self-describing, omit the schema — it’s auto-detected. Switch between the SQL and CLI tabs.

-- Permanent external table over Parquet in the raw zone
CREATE OR REPLACE EXTERNAL TABLE `myproject.raw_zone.sales_ext`
OPTIONS (
  format = 'PARQUET',
  uris   = ['gs://my-raw-zone-bucket/sales/*.parquet']
);

-- Query it like any table
SELECT COUNT(*) FROM `myproject.raw_zone.sales_ext`;
# Equivalent with the bq command-line tool
bq mkdef \
  --source_format=PARQUET \
  "gs://my-raw-zone-bucket/sales/*.parquet" > /tmp/def.json

bq mk --table \
  --external_table_definition=/tmp/def.json \
  myproject:raw_zone.sales_ext
4
Handle Hive partitionsprune by dt so queries don’t scan the whole lake
core▶

If you partitioned by dt in step 1, declare it so BigQuery skips irrelevant folders. Requiring a filter guards against full scans.

GoogleSQL
CREATE OR REPLACE EXTERNAL TABLE `myproject.raw_zone.sales_ext`
WITH PARTITION COLUMNS (
  dt DATE                                -- parsed from dt=YYYY-MM-DD/ path
)
OPTIONS (
  format = 'PARQUET',
  uris   = ['gs://my-raw-zone-bucket/sales/*'],
  hive_partition_uri_prefix     = 'gs://my-raw-zone-bucket/sales',
  require_hive_partition_filter = true
);
5
Create a Cloud resource connectionprerequisite for the BigLake upgrade
upgrade▶

A connection carries a Google-managed service account. Grant that account read on the bucket, so users only need rights on the table — not the raw files.

shell
# 1. Create the connection (location must match dataset + bucket)
bq mk --connection \
  --location=US \
  --project_id=myproject \
  --connection_type=CLOUD_RESOURCE \
  my-gcs-connection

# 2. Read back its service account id
bq show --connection myproject.US.my-gcs-connection
# -> bqcx-....@gcp-sa-bigquery-condel.iam.gserviceaccount.com

# 3. Let that service account read the raw zone
gcloud storage buckets add-iam-policy-binding gs://my-raw-zone-bucket \
  --member="serviceAccount:bqcx-....@gcp-sa-bigquery-condel.iam.gserviceaccount.com" \
  --role="roles/storage.objectViewer"
6
Create the BigLake tableadds WITH CONNECTION + metadata caching
upgrade▶

Same Parquet, now with a connection and metadata caching. Staleness runs 30 minutes to 7 days — tune it to how often PySpark lands new files.

GoogleSQL
CREATE OR REPLACE EXTERNAL TABLE `myproject.raw_zone.sales_biglake`
WITH CONNECTION `myproject.US.my-gcs-connection`
OPTIONS (
  format = 'PARQUET',
  uris   = ['gs://my-raw-zone-bucket/sales/*.parquet'],
  max_staleness       = INTERVAL 1 HOUR,   -- 30 min … 7 days
  metadata_cache_mode = 'AUTOMATIC'
);

-- Force a refresh on demand (e.g. right after a big load)
CALL BQ.REFRESH_EXTERNAL_METADATA_CACHE('myproject.raw_zone.sales_biglake');
7
Query & consumesame for external or BigLake — pruned & aggregated
core▶

Analysts use ordinary SQL. The WHERE dt … filter triggers partition pruning, so only relevant Parquet is scanned.

GoogleSQL
SELECT
  dt,
  SUM(amount) AS total_sales,
  COUNT(*)     AS orders
FROM `myproject.raw_zone.sales_biglake`
WHERE dt BETWEEN '2026-01-01' AND '2026-01-31'   -- prunes partitions
GROUP BY dt
ORDER BY dt;
04 — Decide

Plain external vs BigLake

Both read Parquet in place. BigLake adds a connection and unlocks governance and caching. Google recommends BigLake for anything shared or production.

CapabilityPlain external tableBigLake table
Reads Parquet in placeYesYes
Setup effortNoneNeeds a connection
Access delegationUser needs bucket rightsTable rights only
Metadata cachingNo30 min – 7 days
Row / column securityNoYes
Dynamic data maskingNoYes
Hive partitioningYesYes
Writable (DML)No — read onlyNo — read only
Best forQuick explorationShared / production lake
